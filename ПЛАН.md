# ПЛАН ПРИЛОЖЕНИЯ «ВМЕСТЕ»

## 1. Идея

Не «фитнес-трекер», а **общий дневник заботы двоих**.
Один экран — что я сделал(а) для себя. Второй — что делает любимый человек.
Смысл не в цифрах, а в том, чтобы не забывать про воду, еду, сон и вовремя замечать,
что ей плохо.

Три принципа:

1. **Один тап.** Выпила воды — нажала кнопку. Всё.
2. **Без давления.** Никаких «ты провалила день». Есть мягкий режим, где проценты
   прячутся и остаются только слова поддержки.
3. **Видно друг друга.** Свои данные — локально, а партнёр видит сводку в реальном времени.

## 2. Экраны

### Сегодня
- кольцо воды (SVG, плавная анимация), кнопки +100 / +200 / стакан / +500;
- журнал стаканов с временем, отмена последнего;
- еда: завтрак/обед/ужин/перекус + заметка «что поела»;
- сон: время «лёг → встал», автоматический подсчёт часов (переход через полночь учтён);
- активность: +5/+10/+20 минут, своя длительность, норма 120 минут (рекомендация врачей);
- витамины и лекарства: свой список, галочки на день;
- самочувствие: настроение 5 шкал, флаги «кру`жится голова», «слабость», счётчик «кровь из носа»;
- серия дней подряд;
- баннер входящей записочки/сердечка от партнёра.

### Вместе
- карточка партнёра: аватар-эмодзи, «в сети / был(а) 5 мин назад»;
- его/её сегодня: вода, еда, активность, сон, самочувствие;
- кнопка «💛» — сердечко в один тап;
- быстрые фразы: «попей водички», «поешь», «отдохни», «ты умница»;
- своя записочка текстом;
- сводка недели: моя вода, её вода, баллы.

### История
- календарь 35 дней: цвет = насколько наполнен день, значок 🩸 — если была кровь;
- график воды по дням;
- график кровотечений + мягкий вывод;
- экспорт / импорт JSON.

### Настройки
- имя, эмодзи, цвет;
- вес → автоматический расчёт цели по воде (30 мл на кг, ограничение 1,2–3,5 л);
- цели: вода, стакан, сон, приёмы пищи, активность;
- напоминания о воде (пока приложение открыто);
- мягкий режим;
- список лекарств;
- комната: создать / войти по коду / выйти;
- Firebase: `databaseURL` + `apiKey`, проверка связи;
- данные: экспорт, импорт, стереть всё.

## 3. Модель данных (на телефоне)

Хранится в `localStorage` под ключом `vmeste.v1`.

```js
{
  version: 1,
  me:     { id, name, emoji, color },
  partner:{ id, name, emoji, color },
  room:   { code, joinedAt, host },
  firebase:{ dbUrl, apiKey, uid, idToken, refreshToken, tokenExp },
  settings:{ goalWater, goalSleep, goalMeals, goalActivity, glass, weight,
             soft, reminders, reminderEvery, lastWaterNudge },
  meds:   [ { id, name, ico } ],
  days:   { '2026-11-26': { mine: ДЕНЬ, partner: ДЕНЬ, syncedAt } },
  pending:{ '2026-11-26': 1764… },   // что ещё не улетело в облако
  seen:   { nudge, note, heart },    // что уже прочитано
  partnerLive: { ts, heart, nudge, note }
}
```

ДЕНЬ — документ одного человека за одну дату:

```js
{
  water: [ { t, ml } ],
  meals: { b:false, l:false, d:false, s:false },
  mealNote: '',
  sleep: { from:'23:30', to:'07:00' },
  activity: [ { t, min, kind } ],
  meds: { m1:true },
  feeling: { mood:1..5, nose:0..30, dizzy:false, weak:false, note:'' },
  weight: null,
  updatedAt: 1764…      // время последней правки, решает конфликты
}
```

Балл дня: вода 30 + еда 20 + сон 20 + активность 15 + лекарства 15 = 100.
Балл нужен только для календаря и серии, а не для оценок.

## 4. Синхронизация

Firebase Realtime Database, дерево:

```
rooms/{КОД}/
  meta      { createdAt, host }
  members/{uid}   { name, emoji, color, ts }
  days/{дата}/{uid}   → ДЕНЬ
  live/{uid}      { name, emoji, color, ts, heart, nudge, note }
```

Почему так:

- **каждый пишет только в свой узел** → конфликтов между людьми нет физически;
- правила в `firebase-rules.json` разрешают запись только `auth.uid == $uid`;
- чтение — всей комнате (оба участника);
- партнёр определяется как «другой uid в members».

Механика без SDK:

1. `POST identitytoolkit … :signUp` → анонимный uid и idToken.
   Через час — `securetoken … :token` с refreshToken.
2. `PUT /rooms/{код}/days/{дата}/{uid}.json?auth=…` — запись дня (debounce 700 мс).
3. Живой поток: `GET …?auth=…` с `Accept: text/event-stream`,
   разбор `event: put|patch` вручную → мгновенные обновления без перезагрузки.
4. Очередь: `pending[дата]` хранится на телефоне. Нет сети — копится, при связи улетает.
5. Сторож каждые 45 с: упал поток — перезапуск; сменились сутки — новый поток;
   вкладка в фоне — поток закрывается, чтобы не жечь батарею.
6. Конфликт «телефон ↔ облако»: сравниваем `updatedAt`. Свежее побеждает,
   но несохранённые локальные правки всегда уходят (приоритет у того, кто только что нажал).

Без `apiKey` приложение работает в режиме «открытых правил» (`firebase-rules-open.json`):
проще, но любой, кто знает код комнаты, получит доступ к данным. Для двоих это приемлемо,
но версия с анонимным входом — правильная.

## 5. Безопасность

- uid анонимный, без пароля и почты — регистрация не нужна;
- код комнаты 8 символов из 32 (без похожих букв), ~10¹² вариантов;
- в базе нет ничего, кроме воды и настроения;
- токены лежат в localStorage телефона, в экспорт не попадают (в резервной копии они вырезаны);
- ключ Firebase для веба не секретный — доступ ограничивают именно Rules.

## 6. Технические решения

| Вопрос | Решение |
|---|---|
| Как запускается | один `index.html` + 5 JS-файлов, без сборки и npm |
| Почему без SDK | SDK ~300 КБ, требует модулей; REST+SSE даёт то же самое в 400 строках |
| Почему не APK | на телефоне нет Android SDK; PWA ставится на главный экран и выглядит как приложение |
| Офлайн | localStorage + service worker |
| Хостинг | GitHub Pages (бесплатно, https, ссылка на телефон) |
| Тема | тёмная тёплая, крупные тач-зоны, safe-area, шрифт системный |

## 7. Что сознательно не делаем в v1

- фото еды (нужен Storage и модерация объёма);
- push в фоне (нужен FCM и серверный ключ);
- графики веса и давления;
- чат (для болтовни есть мессенджер, здесь — только записки).

## 8. Дорожная карта

**v1.1** — быстрые шаблоны еды, повтор вчерашнего дня, виджет-ярлык.
**v1.2** — FCM push: «твоя половинка не пила воду 3 часа».
**v1.3** — отчёт недели картинкой (canvas → «поделиться»).
**v1.4** — давление/пульс, интеграция с часами.
**v2.0** — несколько комнат (семья), роли, напоминания по расписанию.

## 9. Что нужно от вас

1. Firebase: создать проект, Realtime Database, включить Anonymous, вставить Rules.
2. Вписать `databaseURL` и `apiKey` в `js/config.js`.
3. Создать комнату и передать код.
4. (по желанию) выложить на GitHub Pages — инструкция в `ЧИТАЙ.md`.

Дальше можно править цели, тексты и внешний вид без пересборки: это обычные файлы.
